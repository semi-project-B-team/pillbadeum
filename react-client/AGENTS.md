##### **에이전트에 넣어야 하는 기본(필수) 지침사항**



## 사용 라이브러리

- 앱이 쓰는 라이브러리는 react, react-dom, react-router, axios, zustand만 쓴다.
- UI 라이브러리와 CSS 프레임워크는 도입하지 않는다.
- TypeScript 문법을 쓰지 않는다.



## 무엇으로 요청하나

- 한 번에 받고 끝나는 요청(JSON 한 덩어리)은 axios 를 쓴다.
- 응답을 조금씩 받아 화면에 흘려야 하는 요청은 fetch 를 쓴다.
ㄴ 예: LLM 이 토큰을 하나씩 내려주는 응답



## 폴더 구조

src/

ㄴ api/         서버 요청. 컴포넌트는 이 파일만 부른다

ㄴ components/  주소에 직접 대응하지 않는 화면 조각

ㄴ pages/       주소 하나에 대응하는 화면

ㄴ store/       여러 화면이 함께 쓰는 값

- 주소에 직접 대응하면 pages, 아니면 components 에 둔다.





## 데이터 요청

- 서버 요청은 api/ 폴더의 .js 파일에만 둔다.
- 컴포넌트(.jsx)에서 axios 나 fetch 를 직접 부르지 않는다.
- API 경로와 파라미터는 OpenAPI 명세를 따른다.



## 상태 관리

- 화면 하나에서만 쓰는 값은 useState에 둔다.
- 여러 화면이 공유하는 값(로그인 정보 등)은 Zustand 스토어에 둔다.
- 새로고침·공유 후에도 유지해야 하는 검색·필터·페이지 조건은 URL 쿼리스트링에 둔다.
- 서버에서 받아 온 목록은 받은 화면이 갖고, 전역 스토어에 넣지 않는다.





## 스타일 규칙

- 색은 반드시 var(--토큰) 으로 쓴다. 색 값을 직접 적지 않는다.
- font-size 를 직접 쓰지 않는다. 타입 스타일 클래스를 쓴다.
- 간격은 --space-\* 스케일 안에서만 고른다.
- 토큰 목록은 design/pillbadeum-tokens.json 을 참조한다.
- 목업의 동작 중 서버 연동이 필요한데 OpenAPI에 해당 API가 없거나 서로 다르면, 임의로 API를 만들어내지 말고 차이를 보고한다.




- 프론트 전체 화면의 구성과 사용자 흐름은 최신 Claude 화면 목업을 기준으로 한다: https://claude.ai/artifact/1oMYiy1DS1aK6wxBt7Zift#page-dcb81aee8d83
- 구현 전 전체 사이트맵과 화면 간 이동 흐름을 파악한다. : https://claude.ai/artifact/C7indq7tzZKoSC49tE3qQz
- 한 번에 전부 구현하지 않고, 공통 구조를 먼저 잡은 뒤 사용자 흐름 순서대로 진행한다.
- 목업에 있어도 OpenAPI에 없는 동작은 임의로 만들어내지 말고 차이를 보고한다.
- 아티팩트 링크를 읽을 수 없다면 추측하지 말고 알려준다.







## 코드 검증

- React 코드를 수정한 뒤 `npm run lint`와 `npm run build`를 실행한다.
- 오류가 나면 원인을 수정하고 두 명령을 다시 실행한다. 경고도 가능한 한 해결한다.
- 검사 결과를 보고할 때 실행한 명령과 성공·실패 여부를 명시한다. 실행하지 못했다면 그 이유를 적는다.
- 린트와 빌드 통과만으로 화면 동작을 확인했다고 말하지 않는다. 화면 기능은 브라우저에서 직접 확인한다.
- ESLint 규칙을 통과시키려고 훅 규칙을 비활성화하거나 `eslint-disable`을 추가하지 않는다. 필요하다면 이유를 먼저 설명한다.



## 명세와 서버

- `design/pill-api-docs.json`은 실행 중인 필받음 백엔드의 `/v3/api-docs`에서 받은 최신 OpenAPI JSON이어야 한다. 현재 폴더에 없으면 먼저 추가하거나 사용자에게 요청한다. 수업 예제의 JSON은 사용하지 않는다.
- 개발 서버 기본 주소는 `http://localhost:8080`이다. axios `baseURL`은 `src/api/client.js` 한 곳에 둔다. 환경별 주소가 달라지면 환경 변수로 전환한다.
- 백엔드의 기본 허용 프론트 출처는 `http://localhost:5173`이다. 포트가 달라지면 CORS 설정과 함께 확인한다.
- API 경로·HTTP 메서드·요청·응답은 OpenAPI JSON을 기준으로 한다. 컨트롤러 코드나 실제 응답과 다르면 차이를 보고한다. 없는 엔드포인트를 지어내지 않는다.
- 요청 함수 위에는 확인된 컨트롤러 메서드와 경로만 짧게 적는다. 이름을 추측하지 않는다.
- 개발 로그에 Bearer 토큰, 비밀번호, 개인 복약 데이터 원문을 출력하지 않는다.


## 기능별 지침

- 인증·회원가입·로그아웃·로그인 만료 처리와 관련된 화면이나 API를 작업하기 전에 `docs/auth-logout.md`를 먼저 읽고 따른다.
- 해당 문서의 화면 ID와 이동 흐름을 최신 목업과 대조한다.
- 문서 내용이 최신 OpenAPI 또는 실제 서버 응답과 다르면 임의로 맞춰 구현하지 말고 차이를 먼저 보고한다.
- 관련 작업을 마친 뒤에는 이 지침의 적용 여부와 확인하지 못한 항목을 함께 보고한다.
