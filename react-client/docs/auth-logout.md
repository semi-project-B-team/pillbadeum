인증 / 로그인, 로그아웃 지침

## 인증 · 로그아웃
- 인증은 Bearer access token 방식이며 Refresh Token은 없다.
- 인증 상태(토큰 · 회원 정보)는 Zustand로 관리한다. 인증이 필요한 요청에는 저장된 토큰을 Bearer 헤더로 보낸다.
- 인증 상태는 Zustand persist로 localStorage에 보관하고, 로그아웃 · 401 처리 시 저장된 상태도 함께 지운다.
- 새로고침하면 저장된 토큰으로 GET /api/auth/me를 불러 회원 정보를 확인한다. 401이면 아래 401 처리를 따른다.
- 새로고침 후 GET /api/auth/me 확인이 끝나기 전에는 로그인 여부를 확정하거나 보호된 화면을 먼저 보여 주지 않는다. 성공하면 회원 정보를 응답값으로 갱신한다.
- 로그아웃 확인창은 로그인 후 모든 화면의 헤더 '로그아웃'에서 열리는 공통 창이다. CMN-01의 홈 배경은 목업 예시일 뿐이다.
- '취소'를 누르면 원래 화면에 그대로 머물고 입력 중이던 내용도 유지한다. 목업 플레이에서 홈으로 이동하는 것은 보드 구성의 한계이며, 실제 구현에서는 홈으로 이동하지 않는다.
- '로그아웃'을 누르면 서버를 부르지 않고 프런트에서 저장된 로그인 정보를 지운 뒤 로그인 화면(MEM-04)으로 간다. 로그아웃 뒤에 뒤로 가기를 눌러도 로그인 후 화면이 다시 보이지 않게 한다.


### 로그인 · 회원가입
- 로그인 직후 프로필 목록(GET /api/profiles)을 불러온다. 0개면 프로필 만들기(PRF-02)로, 있으면 홈(CMN-01)으로 간다.
- 관리할 사람(지금 관리 중인 프로필)은 저장된 값이 이 회원의 프로필이면 그대로 쓰고, 아니면 본인 프로필, 본인이 없으면 목록 맨 위 프로필로 정한다.
- 회원가입이 성공하면(201, 본문 없음) 입력한 이메일 · 비밀번호로 로그인 API를 한 번 더 호출해 자동 로그인하고 프로필 만들기(PRF-02)로 간다. 비밀번호는 이 호출에만 쓰고 저장하거나 다른 화면으로 넘기지 않는다.
- 자동 로그인에 실패하면 "가입이 완료됐어요" 안내와 함께 로그인 화면(MEM-04)으로 간다.

### 로그아웃
- 로그아웃은 확인창(CMN-01 로그아웃 확인)에서 "로그아웃"을 눌렀을 때만 실행한다.
- 로그아웃 시 토큰 · 회원 정보 · 선택한 프로필 · 프론트에 보관된 개인 데이터 캐시를 지우고 로그인 화면으로 이동한다. POST /api/auth/logout은 호출하지 않는다.
- 로그아웃은 서버에 발급된 JWT를 즉시 무효화하지 않는다. 이미 복사된 토큰은 만료 시각까지 유효할 수 있다.

### 401 · 403 · 그 밖의 오류
- 토큰을 붙인 요청에서 401을 받으면 인증 상태를 지우고 로그인 만료 안내 화면(CMN-03)을 보여 준다. "다시 로그인"을 누르면 로그인 화면으로 간다.
- 여러 요청이 동시에 401을 받아도 이 처리는 한 번만 한다.
- 로그인 API의 401 LOGIN_FAILED는 전역 로그인 만료 처리에서 제외한다. 로그인 화면에서 오류 문구만 보여 준다. 회원가입 직후 자동 로그인에 실패한 경우에도 CMN-03이 아니라 가입 완료 안내를 보여 준다.
- 네트워크 오류나 서버 500은 토큰 만료로 간주하지 않는다. 인증이 필요한 요청에서 401이 확인됐을 때만 인증 상태를 지운다.
- 403에서는 자동 로그아웃하지 않고 권한 오류 화면(CMN-02 403)을 보여 준다.
- 사용자가 로그아웃한 뒤 진행 중이던 요청이 뒤늦게 401을 반환해도 로그인 만료 화면을 띄우지 않는다.
